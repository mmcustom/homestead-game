# Homestead
## Art Readiness and Placeholder List v0.8

Status: started 2026-11-04 (Mike's decision); v0.2 added Claude Code's read-only inventory, the swap-point plan and the phases; v0.3 recorded phase A1 as BUILT (ef52c25); v0.4 added the hands swap point (Hands and tools M0a, 73ee84d); v0.5 adds the tool swap points (Hands and tools M0b, 175a8c7). Rough shapes are fine for the Alpha. Better art for everything is wanted eventually, so the code must make replacing placeholders cheap. This doc holds the standing rule, the conventions, the placeholder list, the plan and the style questions.

---

# Why

There is no authored art in the project at all (no .fbx, .blend or .glb). Every mesh is a Unity primitive or a mesh generated by an Editor script and saved under Assets/Art. Structures, piles, shelters and dropped items are drawn in code with GameObject.CreatePrimitive, and there is no swap point: putting a real model in today means rewriting a drawing method. Fixing that later for dozens of things is costly. Fixing it as we build is cheap.

When to pull art forward: showing the game publicly (store page, wishlist trailer, crowdfunding), bringing in an artist (they need a style target and a shopping list), or playtesters judging the game by looks instead of play. Until then the Alpha stays on rough shapes.

"Provide one swap point for a prefab: every new visual (structure, item, tool, hands, effect) has exactly one clearly named place where a prefab can replace the primitive version, with named anchors for anything the code attaches to it (smoke, glow, mouth, hands grip, door, etc.). The primitive version stays as the default. Say where the swap point is in your report."

# Conventions (checked against the code by Claude Code, 2026-11-04)

- 1 Unity unit = 1 metre. Player 1.8 m high, radius 0.35, eye 1.65 m (confirmed). Cabin 4 x 5 m, Kiln dome 2.0 m. Real-world sizes for everything.
- Pivot at the centre of the footprint on the ground (y = 0). Confirmed for pivots. Interaction boxes are NOT centred today (the Smithy's box centre is (-0.07, 0.55, -0.31) because it is the aim box).
- Forward = +Z is the open front (Kiln mouth, Smithy, Workshop, Bloomery). A structure's yaw is the player's yaw, so +Z points away from the player unless the mouse wheel turns it (15 degree steps, only for kinds in FacingMatters). Open sheds start facing downwind (DownwindYaw).
- Named anchor children for everything the code attaches to: Anchor_Smoke, Anchor_Mouth, Anchor_Chimney, Anchor_Stock, Anchor_Door, Anchor_Grip_R, Anchor_Grip_L. A missing anchor falls back to today's rule coordinates.
- Footprints, clearances and reach come from the rules classes, not the art. The interaction box and Solid colliders come from the builders today; the interaction box moves into the spec table one kind at a time.
- One swap point per visual: a single hook that either builds the primitive version or instantiates a prefab found by a fixed id.
- Primitive scale note for authors: a Unity cylinder is 2 units high and 1 across, so scale Y is the half-height. Cubes and spheres use full size.
- HDRP: prefabs must use HDRP-compatible materials.

Known breaks of the conventions (to be tidied only when the anchors replace them):

- Art numbers inside rules classes: SmithyRules.ChimneyX/Z and SmokeHeight/Spread/Size/Rise, CharcoalRules.Smoke*, BloomeryRules.Smoke*.
- Colour tokens are static fields per file (PlacedStructure, Tripod, Tap, DroppedItems), not in one place.
- The Smithy's chimney is a code-created "Chimney" object, not an anchor.
- Interaction boxes are decided by builders, not by a spec table.

# The swap mechanism (planned, phase A1)

- New static ArtSwap resolves an id to Resources/Art/<id>.prefab and caches the result, including "none". Ids: structure_<pilekind>, item_<itemid>, tool_<itemid>, effect_<name>.
- Hook at the top of StructureVisuals.Build, returning early only when a prefab is found. No builder body is edited, so existing tests that pin PlacedStructure.cs source keep passing. The placement ghost runs the same builders, so it gets the swap for free, with a translucent material override on the instance's renderers.
- Anchors are plain child objects found by name. Instantiate strips every collider (as Piece() does); the builder's box stays the one collider; children named Solid_* get colliders back so roofs still shelter (OverheadCover).
- State by named children only: State_Empty, State_Loaded, State_Firing, State_Done; On_Working, On_Burning, On_Smelting for glow and embers; HotPiece for the anvil; Fill_1..Fill_N or one Fill object scaled on Y. If the prefab has its own smoke particle system under the smoke anchor it is toggled, otherwise the code creates KilnSmoke at the anchor with today's numbers.
- Dynamic contents (pieces in the Kiln mouth, Bars outside the Smithy) stay primitives parented to named anchors in the first version.
- With a prefab, Bind instantiates once and Rebuild only toggles named children (cheaper than today's destroy-and-rebuild). Build must tolerate a null pieces list because the ghost calls it that way.
- No gameplay or save change; the prefab holds no saved data. Smallest version: ArtSwap (about 150 lines) plus about 40 lines in StructureVisuals.Build and Rebuild, Kiln only, about 15 to 20 tests.

Worked example, Kiln (Resources/Art/structure_kiln.prefab): Body always on; Anchor_Smoke 1.1 m above origin (matches KilnSmoke.height); Anchor_Mouth 0.95 m forward and 0.45 m up; Anchor_Stock at x -1.45 for firewood; On_Firing glow; State_Empty / Loaded / Firing / Done dome variants chosen by KilnPhaseOf(state); no Solid parts (the Kiln's box is the collider).

# Phases

- A0: docs only (this doc, inventory, corrected conventions). Done when committed.
- A1 (BUILT, ef52c25): ArtSwap, spec table, Kiln pilot, ghost handling. Playtest: drop a cube prefab at Resources/Art/structure_kiln.prefab, see it appear and react to firing, remove it and see today's Kiln.
- Hands and tools M0, right after A1: tool_<id> and Anchor_Grip_R/L through the same ArtSwap (depends on A1 only).
- A2: the other 22 PlacedStructure kinds (anchor spec and state mapping per kind), plus the editor tool "Homestead/Art/Placeholder List" (reads the spec table, shows id, expected prefab path, exists or not, required and optional anchors, size, state names; exports Markdown; warns on bounds mismatch).
- A3: WoodPile family (Wood Pile, Rock Pile, barrels, boxes, rack, shed, shelving, cart). Count-dependent contents are the hard part.
- A4: Shelters (Tent, Tarp, Lean-To, Cabin, hearth anchor).
- A5: World items (DroppedItems), Tripod, Tap. item_<id> is the same prefab later used in hands.
- A6: Existing prefab slots (Campfire, animals, traps) added to the table, no code.
- A7 and A8: Trees, stumps, rocks, grass, forage; water, terrain, weather. After the art style decision.
- One commit per phase.

Risks: trees (SeasonalTrees recolours from per-vertex data baked into leaf faces and snow caps; a replacement mesh without it stays green all year); Solid_* colliders (a prefab without them stops sheltering from rain); six test classes pin PlacedStructure.cs source (avoid refactoring Rebuild's four duplicated smoke blocks in A1); many prefab instances may add draw calls (static batching later); LOD, occlusion and licences depend on the style decision.

Not verified by Claude Code: sizes of barrels, boxes, rack, shed, shelving, cart, Tripod, Tap, Tent, Tarp, Lean-To; the Well's water disc; Kitchen footprint; whether Player.prefab has a body mesh; Carcass visuals; rock outcrop details; whether the small PNGs are generated or hand-made; every Rebuild call site; camera field of view and near clip.

# Decisions (Claude Code's 10 recommendations; ALL ACCEPTED by Mike, 2026-11-04)

1. Resources/Art/<id>.prefab path plus a generated list (a catalogue asset can be added later).
2. Ids: structure_<pilekind>, item_<id>, tool_<id>, effect_<name>.
3. State driven by named children now (no helper component for artists).
4. Dynamic contents stay primitives at anchors in the first version.
5. Interaction boxes move into the spec table, one kind at a time, never all at once.
6. Finished structures only; sites (staged plots) get no prefabs.
7. Pilot kind: Kiln (smoke, glow, phases; KilnTests does not pin PlacedStructure.cs source).
8. Art numbers stay in rules classes until anchors replace them in each kind.
9. The placement ghost uses the prefab with a translucent material override.
10. No auto-fit of a prefab to the footprint; the editor warns on size mismatch instead.

# BUILT: Art readiness A1, ArtSwap and the Kiln pilot (2026-11-04, playtest 1 to 18 passed, committed ef52c25)

The one swap point for structure visuals is the first line of StructureVisuals.Build (Scripts/World/PlacedStructure.cs), which calls ArtSwap.TryBuild (Scripts/World/ArtSwap.cs). A prefab at Resources/Art/<id>.prefab replaces the primitive version when it exists; with no prefab the primitives are drawn exactly as before. The old dispatcher moved unchanged into StructureVisuals.BuildPrimitive (internal); no builder body was edited. The header comment in ArtSwap.cs is the instruction sheet for a prefab author.

How a prefab is used (Kiln, id structure_kiln):

- Instantiated once in Bind as a child named structure_kiln and kept across Rebuild; each Rebuild only switches named children and redraws the contents. The instance root is reset to position zero and no rotation (scale kept), so Anchor_* children must be unrotated and unscaled.
- Body always on. State_Empty, State_Loaded, State_Firing, State_Done follow KilnPhaseOf (Loading and Ready both show State_Loaded). On_Firing shows only while firing.
- Anchors: Anchor_Smoke (1.1 m above origin; KilnSmoke is created there with height 0, or, if the prefab has its own particle system under the anchor, that one is played and stopped), Anchor_Mouth (loaded and fired pieces and Ash, kept as primitives), Anchor_Stock (firewood primitives, left of the Kiln at x -1.45). A missing anchor is created as an empty child at today's position.
- Colliders: every collider in the prefab is removed; children named Solid_* get a box fitted to their mesh bounds (the Kiln has none today); the one BoxCollider still comes from the builder, with today's box. Footprints, setbacks and reach stay in the rules classes.
- The placement ghost goes through the same Build; the existing ghost code puts the translucent green or red material on every renderer on the instance.
- Dynamic contents are copied from the primitive builder: a scratch object draws the primitive Kiln, the 9 fixed shapes are discarded and the contents (Firewood first, then mouth pieces) are moved to the anchors. A test pins the 9-shape and ordering assumption; if the Kiln builder changes, that test says so.

Adding the next kind: one Spec row in ArtSwap.Specs (id, required and optional anchors, state names, expected size, staticPieces and a contentSplit if the builder draws changing contents), plus the kind's drivers in Rebuild. Test seam: ArtSwap.Loader (defaults to Resources.Load), ResetForTests() and ResetCache().

Playtest helpers: editor menu Homestead/Art/Create Test Kiln Prefab (slab body, four coloured State blocks, an orange On_Firing block, a marker cube at each anchor) and Remove Test Kiln Prefab. Create refuses to overwrite an existing prefab; Remove only deletes a prefab that has the TestKiln_Marker child. Never commit Assets/Resources/Art.

Spec values: Kiln expectedSize is 2.4 x 1.1 x 2.4 (pad width and vent height); the interaction box (2.2 x 1.5 x 2.2) is stored separately.

Not covered yet: a prefab with a rotated or scaled Anchor_*; a prefab's own particle system was only tested through isPlaying and isEmitting in edit mode; sites (staged plots) have no prefab by decision.

Save and gameplay: no change; the prefab holds no saved data. SaveVersion and LedgerSaveData stay at 1. Files: 7 paths (PlacedStructure.cs modified; ArtSwap.cs, ArtSwapMenu.cs, ArtSwapTests.cs new, with metas), 1057 insertions and 2 deletions. Edit-mode suite 1609 of 1609 (27 new tests).

Swap points so far (for the standing rule): FireManager.campfirePrefab, WildlifeManager species prefabs, trap and bobber prefabs (existing), and ArtSwap structure_<pilekind> (Kiln only), ArtSwap hands_player (first-person hands, M0a, 73ee84d), and ArtSwap tool_<itemid> (eight tools in hand, M0b, 175a8c7; four more, M0c-1, 0d6cdd3: fishing_rod, cane_pole, torch, lantern). Everything else in the placeholder list still has no swap point; phases A2 to A8 add them.

Next: hands and tools (tool_<id>, Anchor_Grip_R/L through ArtSwap), then A2 (the other structure kinds and the editor placeholder list).
